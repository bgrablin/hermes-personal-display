## Display decision

No new runtime contract is needed for this range. The current display already handles the useful merged evidence, and binding an unmerged Kanban or approval proposal would be premature. This checkpoint therefore records compatibility and deployment decisions without manufacturing another UI state.

The display RPC monitor remains a passive exact-owner reader. It does not attach/resume a session, replay commands, render server-to-client requests, or answer approvals. It must not advertise `server_requests: true` merely to look current; doing so would claim a response lifecycle it does not implement and could redirect a live approval or clarification away from the owning TUI/Desktop client.
