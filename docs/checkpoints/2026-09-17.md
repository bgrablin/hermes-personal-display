## Display decision and implementation

Hermes main now distinguishes a human stop from lifecycle/watchdog interruption in the canonical `on_session_end.turn_exit_reason`. The display previously collapsed both into one generic interruption, which could falsely imply that a person stopped a turn.

The candidate:

- accepts only the bounded structured forms `interrupted_by_user`, `interrupted_during_api_call`, `interrupted_by_system(<safe issuer>)`, and `interrupted_during_api_call(<safe issuer>)`;
- rejects arbitrary exit/error prose and never exports it into the browser packet;
- retains user-requested interruptions as amber, while system interruptions become a coral `TURN INTERRUPTED` card with `Stopped by Hermes`, a normalized issuer, provider-request phase when present, and the observed surface;
- resolves a system interruption to `needs_attention` without calling it a tool/provider failure, and continues to account for surviving processes, delegations, subagents, and tools independently;
- adds schema/generated-contract coverage, focused observer/resolver tests, a two-viewport browser case, plugin version `1.3.0`, and an inspected synthetic 1200×800 preview;
- preserves the smaller eye, blue motes, private-home detail policy, targeted credential redaction, safe DOM rendering, and family-mode separation. No interrupt, retry, replay, or approval control is added.
