## Display implementation

- `Observer` retains at most 64 turn-scoped calls keyed by exact `tool_call_id`; no tool arguments or result payloads are retained.
- `pre_tool_call` creates a running observation. The exact terminal `post_tool_call` independently records status and duration. A completion without a matching start is labeled as such.
- A parent turn that ends with a still-running call changes it to `unknown` rather than success. Exact tool errors contribute to recent failure state.
- The ambient projection exposes only a generic active-call count. The loopback operator inspector adds blue, touch-readable cards with tool name, exact call/turn IDs, status and duration; it renders text nodes only.
- The first identity-bearing event from a new turn rotates the call rail. Prior unknown evidence is retained as a fail-closed outcome; independently owned processes, delegations and subagents are unchanged.
- Unknown tool evidence cannot be evicted as settled session/rail capacity. Exact concurrent counts remain bounded to 64 through public-packet sanitization.
- Smaller eye, blue motes, truthful non-pipeline activity, targeted credential redaction, private-home details and family-mode exclusion are unchanged.
