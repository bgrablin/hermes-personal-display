## Display decision

Add a read-only, profile-scoped view of Hermes' durable `cron_incidents` ledger.

- Recent open incidents (24 hours) give the otherwise-idle landscape display an amber scheduler notice and one bounded eye reaction.
- Active work still wins the primary activity card; a scheduler failure is not presented as current execution.
- Older unresolved incidents remain available in the private touch inspector without sustaining the ambient alarm.
- `resolved` and operator-acknowledged `closed` incidents are excluded.
- The display never acknowledges, retries, replays, adopts, or changes ownership of a run.
- Job names, profile identities, selected errors and output paths remain useful on the private display. Existing credential-targeted redaction and safe DOM rendering remain in force. Family mode receives no incident payload.

## Candidate implementation

- Reads each bounded, non-symlinked profile's `cron/executions.db` using SQLite read-only mode.
- Resolves useful task names from bounded `cron/jobs.json` reads.
- Counts all recent/open rows independently of the five-card display limit.
- Fails closed rather than presenting partial totals if any discovered ledger is unreadable or lacks the incident table.
- Keeps errors, output paths and other detailed evidence on the loopback-only inspector endpoint; the ambient state packet receives only the fields needed to render the notice.
- Adds contract fields under `live.cron_incidents`, server sanitization, private inspector cards, landscape notice and browser regressions.
